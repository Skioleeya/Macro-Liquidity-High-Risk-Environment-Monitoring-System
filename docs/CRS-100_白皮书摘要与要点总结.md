# CRS-100 白皮书摘要与要点总结

- **对象文档**：`美股宏观流动性与高风险环境日线监控系统（CRS-100）白皮书与业务逻辑规格书`
- **整理日期**：2026-10-15
- **阅读约定**：`原文` = 白皮书明确写出；`推断` = 白皮书未写、由上下文推导，已逐条标注。

## 0. 一句话判定

这是一份**技术规格书**，不是商业计划书。技术路线、因子设计、执行规程写得相当完整；**商业模式、目标用户画像、竞争分析、验证证据（回测/命中率）四项完全缺失**——下文逐项标注。

## 一、核心目标

| # | 目标 | 原文依据 |
|---|---|---|
| 1 | 为宏观窗口 **T-5 ~ T+3** 的跨资产与衍生品交易，提供**日线级底层风控基准** | "为宏观时间窗口（T-5 至 T+3）的跨资产博弈与衍生品交易提供日线级别的底层风控基准" |

## 二、目标用户

> ⚠️ **白皮书未定义用户。** 全文出现"机构 / 交易员 / 对冲基金 / Risk Parity / Vol-Targeting"，但这些都是**被建模的市场参与者**，不是客户。

从执行条款反推（**推断**）：

- 具备**期权与期货下单权限**的自营台或基金交易台（六.1 要求削减衍生品 Delta 净敞口 50%；六.3 要求账户 Max Risk 锁定在净值 **1.50%** 内）。
- 做**宏观事件驱动**、持仓跨日以上，不依赖日内分时（系统本身是 EOD 的）。
- **成本极敏感**——"零数据成本"被当作卖点，说明目标用户不愿为 SpotGamma / SqueezeMetrics 类数据付费。
- 有能力人工执行 18:00 ET 前的"得分审计"（六.1）→ 排除纯被动 / 零售用户。

## 三、主要功能模块

系统为**五层流水线 + 三个决策层**。

### A. 采集层（Task 1 Ingestion）

| 数据源 | 字段 |
|---|---|
| FRED | `WALCL`、`WTREGEN`、`RRPONTSYD`、`BAMLH0A0HYM2`、`DEXJPUS` |
| CBOE 日末 | Total PCR、Equity PCR、Index PCR |
| yfinance | `^GSPC`、`^VIX`、`^VIX9D`、`^VIX3M`、`DX-Y.NYB`、`^TNX`、`CL=F` |

### B. 清洗对齐层（Task 2 Normalization）

前向插值处理美联储周度滞后 → 60D Z-Score（Net Liquidity）+ 5D 动量 → 20D Z-Score（PCR）→ 波动率斜率比。

### C. 日历规则层（Task 3 Calendar）

回购静默期 / 月度 OPEX / FOMC 静默期，布尔加权树。

### D. 评分与产出层（Task 4）

四维加权融合 → 状态判定 → Markdown 策略看板 + 告警日志 + 本地时序库。

### E. 分析内核：四维因子矩阵（权重严格闭合 100.00%）

| 维度 | 权重 | 代理指标 | 关键阈值 |
|---|---|---|---|
| 一 · 货币财政净流动性 | **30%** | `WALCL − WTREGEN − RRPONTSYD` 的 60D Z + 5D 变动 | `Z ≤ −1.5` 且 `Δ5D < −2.0%` |
| 二 · 衍生品 / Gamma 代理 | **25%** | `ΔPCR = Total PCR − Equity PCR`；`Z_TotalPCR`；`VCT = 0.6·(VIX9D/VIX) + 0.4·(VIX/VIX3M)` | `VCT > 1.05` 且 `Z_TotalPCR > 1.5` |
| 三 · 信用利差与融资压力 | **25%** | HY OAS 绝对水平 + 20D 偏离；USD/JPY 5D；US10Y | `OAS > 420bps` 或 `Δ20D > +35bps` |
| 四 · 制度性日历 | **20%** | 回购静默(8) + OPEX(6) + FOMC 静默(6) | 三项布尔加总（8+6+6=20 ✓） |

### F. 做市商 Gamma 代理状态机（自建核心）

四种模式：**正 Gamma 抑制** / **中性转换** / **负 Gamma 加速** / **Vanna 逼空**。

### G. CRS-100 分级 → 策略映射

| 区间 | 标签 | 仓位动作 | 期权结构 |
|---|---|---|---|
| **75–100** | 一级高危清算 | 多头敞口降至 **30% 以下**，禁左侧抄底 | Long Put / Bear Put Spread |
| **50–75** | 二级剧烈洗盘 | 控制在 **50–60%**，拒绝追单 | Calendar Spread / Iron Condor |
| **0–50** | 三级良性扩张 | 维持 **80–100%** 进攻 | Bull Call Spread |

### H. T-1 盘前执行规程（三步）

1. 得分审计与强制去杠杆（CRS 由 <50 跳至 >75 触发）；
2. PCR × 期限曲率共振校验（倒挂 + Total PCR 破 1.20 → 禁限价单接刀，等 30 分钟）；
3. 跨资产情景对冲（US10Y / DXY / WTI 锚点，Max Risk ≤ 净值 1.50%）。

## 五、竞争优势

原文明确主张的 6 条：

1. **零数据成本**——替代商业 Net GEX（隐含对标 SpotGamma / SqueezeMetrics / Tier1Alpha 类付费产品）。
2. **官方免费源 → 可复现**——FRED + CBOE 官方日末，不依赖黑箱厂商。
3. **无日内基础设施**——EOD 单次运算，工程复杂度与运维成本低。
4. **多维度正交设计**——流动性 / 衍生品 / 信用 / 日历四条独立物理链路，非单信号。
5. **算术可审计**——权重显式闭合 100.00% 并附自洽校验；阈值全部写死可见。
6. **输出可执行**——不只给分数，直接给仓位比例与期权结构建议。

**推断的差异化立论点**：把"做市商 Gamma 环境"从付费高频数据**降维成免费日末代理**——如果代理有效的话。

## 六、潜在风险

### 6.1 模型有效性（最高优先级）

- **PCR → 做市商 Gamma 是弱因果推断。** PCR 是**成交量合约数之比**，不含持仓方向（谁多谁空），无法区分买卖方，也无法区分做市商与终端客户。全文反复用"代理"二字，说明作者清楚这是间接指标——但**代理在什么条件下失效，文档没给边界**。
- **核心归因假设会被打破。** "机构买指数 Put、散户买个股"这一假设，在 0DTE SPX 占比上升、covered-call ETF（系统性卖 Call）规模扩大、个股期权散户买 Put 的情形下会**直接污染 ΔPCR 的读数方向**。
- **阈值全部没有验证证据。** `Z ≤ −1.5`、`VCT > 1.05`、`OAS > 420bps`、`P80`、`Total PCR 1.20`……**全文零回测、零命中率、零误报率**。一套纯阈值规则集，没有任何证据表明它在历史宏观事件上优于抛硬币。**这是本方案最大的空白。**
- **`VCT` 的 0.6 / 0.4 权重未给来源**，看起来是经验取值而非拟合结果。

### 6.2 数据与工程

- **频率错配（逻辑缺陷）**：`WALCL`、`WTREGEN` 是**周度**序列（H.4.1），`RRPONTSYD` 是**日度**。前向插值填平后再算 **5 日 Net Liquidity 变动率**，该变动在多数交易日里其实是**同一批周度数据的重复计算**，Δ5D 的"5 日"含义失真。要么改周度对齐，要么把 Δ 定义在真实更新节点上。
- **单位不一致**：`WALCL`、`WTREGEN` 单位为**百万**美元，`RRPONTSYD` 单位为**十亿**美元。公式 `WALCL − WTREGEN − RRPONTSYD` 若不显式换算，结果无意义。文档未提换算步骤。
- **修订 / 前视偏差**：FRED 序列会被修订（尤其 H.4.1 与 OAS）。未提 ALFRED / vintage 处理 → 直接回测会引入前视偏差。
- **依赖非官方源**：`yfinance` 无 SLA、接口经常变动；CBOE CSV 端点格式历史上变更过。二者均无兜底 / 校验机制描述。
- **"本地时序数据库"未定义**：无选型、无 schema、无幂等 / 回补策略。
- **CBOE PCR 是聚合量**：无行权价、无到期日、无 OI 分布 → **无法还原 Gamma 分布**。文档出现"Gamma 翻转线（Flip Point）"一词，但现有数据**算不出该指标**。

### 6.3 规格自洽性（可直接指出的硬缺陷）

1. **同一状态有三套阈值。** 正 Gamma 的 VCT 门槛在正文出现 **0.90 / 0.92 / 0.95** 三个值；负 Gamma 判定分别用 `Z_TotalPCR > 1.5`、`ΔPCR > P80`、`Total PCR > 1.20` 三种口径。
2. **计分区间存在覆盖空洞。**
   - 维度一：`Z ≥ 0.5` 但 `Δ5D ≤ +1.5%` 时无规则；`Z ≤ −1.5` 但 `Δ5D ≥ −2.0%` 时无规则。
   - 维度三：`OAS < 340` 但 `Δ20D > +35bps` 时无规则。
3. **区间给的是分数段而非点值。** "计 25–30 分""计 10–24 分"——**段内如何取值未定义**。导致 CRS-100 **不是确定值**，同一输入可得不同输出。而系统的唯一输出就是这个分数，此处必须补插值 / 映射规则。
4. **"全自动闭环"与人工步骤矛盾。** 一.2 称全自动，六.1 却要求人工在 18:00 ET 前完成"得分审计"。
5. **分级切换无迟滞。** 50 / 75 硬切换、无确认窗口，易在阈值附近来回抖动（只有 Vanna 模式带"连续 3 日"条件）。

### 6.4 运营与行为

- **EOD 系统在它最需要保护的窗口里是盲的。** 文档自己写"严禁在数据公布瞬间用限价单接刀"——恰恰承认系统无法在盘中提供保护，只能事前降仓。
- **单一维护者风险。** 日历规则（FOMC 日程、财报季、回购窗口）需人工维护更新，无来源与更新机制说明。
