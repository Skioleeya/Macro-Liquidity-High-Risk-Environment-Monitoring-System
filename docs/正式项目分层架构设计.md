# CRS-100 正式项目分层架构设计（L0–L7 + 横向重放）

- **版本**：v1 / 2026-10-15
- **依据**：白皮书第二、三、四、五、六章的业务逻辑；结合 `mvp/` 已实测的结论
- **状态**：设计稿，待 KAI 裁定第 10 节的前置决策后定稿

---

## 0. 本文要解决的问题

白皮书第五章给了四段式流水线（Ingestion → Normalization → Calendar → Scoring），但那是**按执行顺序**切的，不是按**依赖方向**切的。直接照它建项目会出现三个后果：

1. 日历规则既要读外部数据、又要参与打分，会同时依赖上层和下层，破坏单向依赖；
2. "归一化"和"算 Z-Score"混在一段里，阈值和窗口参数散落各处，无法单独验证；
3. 打分层没有前置的验证手段 —— 而白皮书恰恰零回测。

所以本文按**依赖方向 + 变化频率**重新切层，并把白皮书已暴露的缺陷逐一指派到具体层去解决（见第 8 节）。

---

## 1. 划分依据（三条原则）

| 原则 | 含义 | 判据 |
|---|---|---|
| **按变化频率切** | 越靠下越稳定、越通用；越靠上越易变、越贴近业务 | 改一条打分阈值，不应触碰任何 L0–L3 代码 |
| **按依赖方向切** | 只允许 Ln → L(n-1)，禁止反向 | 用导入关系可机械校验 |
| **按"能不能单独验证"切** | 每一层都要有独立于上层的验证手段 | 该层能否在不知道上层存在的前提下跑通并自检 |

补充一条硬约束：**L2–L5 必须是纯函数 + 显式日期参数**，不得依赖"现在几点"。这是重放/回测能成立的前提，也是白皮书最缺的能力。

---

## 2. 分层总览

| 层 | 名称 | 一句话职责 | 产物 |
|---|---|---|---|
| **L0** | 基元层 | 单位、时间、配置、取数、脱敏 | 能力，无产物 |
| **L1** | 接入层 | 每个外部源一个适配器，取回并解析成带单位的观测 | `Observation` 流 |
| **L2** | 归一化层 | 把异构观测对齐成可比面板，并做新鲜度门禁 | `Panel` |
| **L3** | 因子层 | 每个物理维度算出一个原始因子值 | `FactorReading` |
| **L4** | 打分层 | 把物理量按唯一阈值表映射成分项得分 | `SubScore` |
| **L5** | 合成层 | 加权融合、状态机、分级 | `CRSReport` |
| **L6** | 决策层 | 把 CRS 报告映射成执行动作 | `ActionPlan` |
| **L7** | 输出层 | 看板、告警、落盘；对外分发边界 | 看板 / 告警 / 时序库 |
| **横向** | 重放骨架 | 按历史日期重放 L2→L5，供标定与回归 | 回测结果 |

---

## 3. 逐层定义

### L0 基元层

- **职责**：提供与业务无关的能力。**不知道 WALCL 是什么，也不知道什么叫 PCR。**
- **模块**：`config`（配置加载与密钥）、`units`（单位换算）、`net`（HTTP 取回与脱敏）、`clock`（交易日历基元）、`log`
- **核心功能**
  - 配置：缺键 / 空值 / 格式错一律抛错，**不含任何业务默认值**
  - 单位：全系统唯一的换算入口；跨物理量族换算直接拒绝
  - 取数：报错文本必须抹除密钥，并切断异常链
  - 日历基元：交易日、假期、第 N 个周五等**纯日期计算**（不含"OPEX 算不算风险"这种判断）
- **产物**：无
- **不变量**
  - 零业务常量
  - 调用方不得自行乘除换算系数
  - 密钥永不进入任何输出
- **配置**：无（仅 `.env` 提供密钥）

> **为什么日历基元在 L0**：第 3 个周五是纯日期事实，任何项目都能用；而"OPEX 期间算 6 分"是业务判断，属于 L3/L4。混在一起会让日历模块同时被上下两层依赖。

---

### L1 接入层

- **职责**：把每个外部系统封装成一个适配器。**换源不影响上层。**
- **模块**：`sources/fred.py`、`sources/cboe.py`、`sources/yahoo.py`、`sources/fed_calendar.py`（FOMC 日程）
- **核心功能**
  - 取回 + 解析
  - **给每个值贴上单位标签**（来自配置声明，不靠猜）
  - 记录 `retrieved_at`（用于新鲜度判定与审计）
  - 与权威源对账：FRED 的 `units_short` 必须与配置声明一致，不一致即报错
- **产物**：`Observation(series_key, date, value: Decimal, unit, source, retrieved_at)`
- **不变量**
  - 每个观测必带 `unit` 与 `source`
  - 解析失败必须抛错，**不得返回空值或默认值**
  - 密钥不得出现在任何错误文本
- **配置**：`sources.toml`（端点、序列 ID、单位、单位对照表）

> **实测约束（已确认）**：CBOE 已无公开 CSV 端点，PCR 只能从服务端渲染页面解析 → 适配器必须带**离线样例回归**，CBOE 一改版立刻报红。ICE BofA 的 OAS 在 FRED 上只剩 3 年历史，这一约束要在 L1 就记录，供 L3/L4 声明回测边界。

---

### L2 归一化层

- **职责**：把"异构"变成"可比"。**这是所有统计计算的前提，也是白皮书最薄弱的一环。**
- **模块**：`align`（时间轴对齐）、`convert`（单位归一）、`staleness`（新鲜度门禁）、`panel_store`（面板落盘/读取）
- **核心功能**
  1. **交易日轴构建**：以 NYSE 交易日为准，含假期
  2. **频率对齐**：周度序列（`WALCL`/`WTREGEN`）到日度轴。**填充语义必须显式声明**，且填充点打标
  3. **单位归一**：全部换算到配置声明的目标单位
  4. **新鲜度门禁**：每个序列声明 `max_staleness_days`，超限即 **fail-closed**（不是警告）
  5. **面板落盘**：产出可重放的长表
- **产物**：`Panel` —— 长表 `(date, series_key, value, unit, fill_flag, source_as_of)`
- **不变量**
  - 同一 `series_key` 同一日期只有一条记录
  - **任何填充点必须带 `fill_flag`，不得伪装成真实观测**
  - 面板内所有值单位一致
  - 面板必须自带 `source_as_of`（该值的真实数据日期），供下游判断
- **配置**：`normalization.toml`（填充策略、新鲜度上限、目标单位、日历源）

> **为什么 `fill_flag` 是硬要求**：白皮书说"前向插值保证时序无跳空"，但插值后的点如果被当成观测参与 Z-Score 和 Δ 计算，**滚动统计量会被静默污染**。实测已确认：今天 `WALCL` 停在 2026-10-07（滞后 8 天），按白皮书"填充后算 5 日变动率"，该变动在多数交易日里是同一批周度数据的重复计算。打标之后，L3 才有机会说"这个 Δ 只对周度更新节点有意义"。

---

### L3 因子层

- **职责**：每个物理维度一个模块，从面板算出**原始因子值**（不是分数）。
- **模块**：`factors/net_liquidity.py`、`factors/gamma_proxy.py`、`factors/credit_stress.py`、`factors/calendar.py`
- **核心功能**
  - 滚动标准化（60D / 20D Z-Score）、比值、差值、变动率
  - 日历因子的布尔判定（回购静默 / OPEX / FOMC 静默）
- **产物**：`FactorReading(factor_key, value: Decimal, unit, as_of, window, inputs)`
- **不变量**
  - **四个维度之间零依赖**，不得互相 import
  - 每个因子必须能报出它的输入（哪些序列、哪个日期）→ 可复现
  - 窗口历史不足时必须抛错，**不得用部分窗口凑**
- **配置**：`factors.toml`（各因子的窗口长度、定义）

> **为什么日历因子也在 L3**：它输出的是"因子值"（0/1 或原始分），和另外三个维度同构。它比另外三个多一个输入源（L1 的 FOMC 日程），但依赖方向不变。

---

### L4 打分层

- **职责**：把物理量按规则映射成 0–100 的分项得分。**纯规则映射，不做任何计算。**
- **模块**：`scoring/rules.py`（规则引擎）、`scoring/thresholds.py`（唯一阈值表加载）、`scoring/interpolate.py`（分数段→点值）
- **核心功能**
  1. **唯一阈值表**：白皮书里同一状态出现三套口径，此层必须裁定为一套
  2. **分数段→点值**：白皮书给的是"计 25–30 分"这种区间，必须补插值规则
  3. **覆盖空洞兜底**：白皮书存在规则未覆盖的组合，必须显式定义
  4. **规则命中留痕**：每条规则有 `rule_id`，命中即记录
- **产物**：`SubScore(dimension, score: Decimal, band, fired_rule_ids)`
- **不变量**
  - **阈值只存在于本层的配置里**，L4 之外任何地方不得出现阈值数字
  - 输出必须是**确定值**，不得是区间
  - 每条得分必须能回溯到 `rule_id`
- **配置**：`scoring.toml`（阈值、分数段、插值规则、兜底规则）

> 白皮书当前的三处硬缺陷（三套阈值 / 覆盖空洞 / 区间非点值）**全部在此层解决**，且必须在下游 L5 开始前解决 —— 否则 L5 的 CRS 不是确定值，整个系统没有唯一输出。

---

### L5 合成层

- **职责**：加权融合 + 状态机 + 分级。**只做合成，不引入新的物理判断。**
- **模块**：`composite/weights.py`、`composite/regime.py`（状态机）、`composite/grading.py`（分级）
- **核心功能**
  - 四维加权求和 → CRS-100
  - 启动时校验权重和 = 100.00%
  - 做市商 Gamma 代理状态机（正 / 中性 / 负 / Vanna）
  - 三级分级（一级高危 / 二级洗盘 / 三级良性）
  - **迟滞**：分级与状态机切换带确认窗口，避免阈值附近抖动
- **产物**：`CRSReport(crs, level, regime, subscores, fired_rules, as_of)`
- **不变量**
  - 权重和必须严格 = 100.00%，不等即**拒绝启动**
  - `crs ∈ [0, 100]`
  - 状态机切换必须满足确认条件，单日穿越不切换
- **配置**：`composite.toml`（权重、状态机阈值、分级阈值、确认窗口）

> **为什么权重校验要在启动时**：白皮书把"算术自洽校验"写成了文档里的一句话。做成启动断言之后，它才是机制而不是承诺。

---

### L6 决策层

- **职责**：把 `CRSReport` 映射成执行动作。**只做映射，不做计算。**
- **模块**：`playbook/positions.py`（仓位）、`playbook/structures.py`（期权结构）、`playbook/t1_protocol.py`（T-1 规程）
- **核心功能**
  - 分级 → 仓位比例、期权结构、止损规则
  - T-1 三步规程（得分审计 / PCR 与曲率共振校验 / 跨资产情景对冲）
  - Max Risk 上限校验（白皮书要求 ≤ 净值 1.50%）
- **产物**：`ActionPlan(positions, structures, stops, max_risk, rationale)`
- **不变量**
  - 每个动作必须能回溯到触发的 `rule_id` 或 CRS 分级
  - Max Risk 超限即报错
- **配置**：`playbook.toml`

> **注意矛盾点**：白皮书一处说"全自动闭环"，另一处要求人工在 18:00 ET 前完成"得分审计"。本层只产出**建议动作 + 审计视图**，不假设无人值守。

---

### L7 输出层

- **职责**：格式化与投递。**只做格式化，不做判断。**
- **模块**：`delivery/dashboard.py`（Markdown 看板）、`delivery/alerts.py`（告警）、`delivery/timeseries.py`（时序库写入）、`delivery/export_guard.py`（分发边界）
- **核心功能**
  - 生成看板、告警日志、落盘时序库
  - **分发边界检查**：ICE BofA 数据（`BAMLH0A0HYM2`）的授权条款是"internal use only / 禁止再分发"，对外产物必须剥离受限制字段
- **产物**：看板文件、告警、时序库记录
- **不变量**
  - 输出层不得包含任何阈值判断或计算
  - 标记为"仅内部"的字段不得进入对外产物
- **配置**：`output.toml`

> **为什么把"分发边界"放在最上层**：ICE 的限制是**分发**限制，不是**使用**限制。内部计算照用不误，但出口只有一个地方，管住这一个地方就管住了合规风险。

---

### 横向 · 重放骨架

- **定位**：**不是一层**，而是与 L2–L5 并列的消费者，不修改它们。
- **成立前提**：L2–L5 全部是纯函数 + 显式日期参数，不读"现在"。
- **用途**
  1. **阈值标定**：给 L4 的阈值提供历史证据（白皮书完全缺失的部分）
  2. **命中率统计**：CRS 分级与后续实际波动的对应关系
  3. **回归**：改任何一层后重放历史，比对差异
- **产物**：回测结果（命中率、误报率、分级分布）

## 4. 层间契约

| 由 → 到 | 契约 | 关键字段 |
|---|---|---|
| L1 → L2 | `Observation` | `series_key, date, value, unit, source, retrieved_at` |
| L2 → L3 | `Panel` | `date, series_key, value, unit, fill_flag, source_as_of` |
| L3 → L4 | `FactorReading` | `factor_key, value, unit, as_of, window, inputs` |
| L4 → L5 | `SubScore` | `dimension, score, band, fired_rule_ids` |
| L5 → L6 | `CRSReport` | `crs, level, regime, subscores, fired_rules, as_of` |
| L6 → L7 | `ActionPlan` | `positions, structures, stops, max_risk, rationale` |

契约由**生产者层**定义，消费者只读不写。

---

## 5. 依赖与衔接规则

1. **只允许 Ln → L(n-1)**，反向导入一律视为缺陷，用导入关系机械校验。
2. **L0 被所有层依赖**，这是唯一允许的"被向下穿透"。
3. **同层内模块不得互相 import**（尤其 L3 的四个维度）。
4. **配置文件彼此独立**：每层一份，禁止 `$ref` / `include` / `extends`，禁止一个文件含跨层变量。
5. **阈值只在 L4 出现**；权重只在 L5 出现；仓位比例只在 L6 出现。
6. **每个文件 < 400 行**；超限即拆，拆分后靠回归证明行为不变。

## 6. 搭建先后顺序及原因

| 阶段 | 内容 | 为什么是这个位置 |
|---|---|---|
| **0** | L0 + L1 | 已完成。单位与时间错了会污染全部下游，必须最先锁死 |
| **1** | **L2 归一化 + 新鲜度门禁** | 不解决频率错配和填充打标，L3 算出来的全是脏数，后面全白做 |
| **2** | **重放骨架** | **必须早于 L3/L4。** 白皮书零验证，没有重放能力就无法给任何阈值提供证据 —— 先有尺子再量东西 |
| **3** | L3 三个低风险维度（净流动性 / 信用 / 日历） | 数据源已确认、物理机制直白、**不含代理假设** |
| **4** | **阈值标定（研究任务，非编码）** | L4 的前置。用阶段 2 的骨架在历史上定阈值与插值规则 |
| **5** | L4 打分 | 阈值裁定完成后才能写，否则写出来的是一套无法证伪的规则 |
| **6** | L3 的 `gamma_proxy` + 对应打分 | **放最后。** 它是白皮书的核心创新，也是最大风险（PCR→做市商 Gamma 是弱因果推断，且归因假设会被 0DTE / covered-call ETF 污染）。应先有验证框架，再单独验证它 |
| **7** | L5 合成 | 依赖 L4 输出确定值 |
| **8** | L6 决策 | 依赖 L5 分级 |
| **9** | L7 输出 | 依赖 L6 动作；放最后是因为它最容易诱导"用图好看代替数正确" |

**三条不能反过来的理由**

- 先做 L4 再做重放骨架 → 阈值变成拍脑袋且无法证伪，正是白皮书当前的病。
- 先做 `gamma_proxy` → 把最大的不确定性放在最前面，后面全是返工。
- 先做 L7 看板 → 看板会跑得比数据对，产生"系统已经能用"的错觉。

## 7. 关键业务流转（一个完整交易日）

```
16:30 ET 收盘触发
  │
  ├─ L1 取数        FRED 5 序列 + CBOE PCR/波动率 + Yahoo 7 代码
  │                 失败点：CBOE 页面改版 / Yahoo 限流(已实测 429) / 密钥无效
  │
  ├─ L2 对齐+门禁   交易日轴 → 频率对齐(打 fill_flag) → 单位归一 → 新鲜度检查
  │                 失败点：WALCL 滞后 8 天 → 由 max_staleness 决定放行还是 fail
  │
  ├─ L3 四因子      净流动性 / Gamma 代理 / 信用压力 / 日历
  │                 失败点：窗口历史不足
  │
  ├─ L4 打分        四维各自 → 0–100 分项分（带 rule_id）
  │                 失败点：规则未覆盖的组合
  │
  ├─ L5 合成        加权(校验 100.00%) → CRS → 状态机(带迟滞) → 分级
  │
  ├─ L6 决策        仓位 / 期权结构 / 止损 / MaxRisk 校验
  │
  └─ L7 输出        看板 + 告警 + 时序库；对外产物过分发边界检查

次日 T-1 盘前
  └─ 读 L7 产物 → 按 L6 动作执行
18:00 ET 人工审计（L7 提供审计视图）
```

**全程可重放**：把"16:30 ET"换成任意历史日期，L2→L5 应能完整重跑并给出当时的结果。

## 8. 白皮书缺陷 → 归属层对照

| 白皮书缺陷 | 解决层 | 方式 |
|---|---|---|
| 单位混用（百万 / 十亿） | L0 + L2 | 单位令牌 + 强制换算，无"直接相减"入口 |
| 周度 / 日度频率错配 | L2 | 显式填充语义 + `fill_flag` 打标 |
