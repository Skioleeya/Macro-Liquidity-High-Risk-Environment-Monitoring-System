# Project State — L2 归一化层

本文件只放"为什么"。事实与命令证据在 `handoff.md`，基线在 `startup.md`。

## 1. 裁定：假期规则数据放哪里（`startup.md` 风险 1）

架构文档第 3 节把"交易日、假期"列在 L0 `clock` 下，但同节的 L0 配置行写"无（仅 `.env` 提供密钥）"。
假期规则会增删（Juneteenth 2022 才生效）、会临时休市（2024 年卡特国葬），它是**数据**。
L0 无配置 ⇒ 数据没地方放。

**裁定**：拆成两半。
- `L0_基元层/clock.py` 只放**纯日期算术**（第 N 个星期几、复活节、周六周日顺延），零数据、零配置。
- 假期规则本身进 `config/normalization.toml` 的 `[calendar]`，由 `L2_归一化层/calendar.py` 求值。

**被否决的方案**：把 NYSE 假期表写进 `clock.py` 的常量。否决理由 —— 那会让 L0 含业务常量，
且交易所改一次规则就要改 L0 代码，正好违反"改一条打分阈值不应触碰 L0"的划分原则。

## 2. 裁定：同层 import 与"契约由生产者层定义"的冲突（`startup.md` 风险 2）

第 4 节说"契约由生产者层定义"，第 5.3 节说"同层内模块不得互相 import"。
`Panel` 由 L2 定义 ⇒ `panel_store` / `align` 读它必然是同层 import。

**裁定**：`check_layering.py` 引入两类**显式声明**，且声明本身被机械校验：

- `SHARED_MODULES`（层内共享叶子）：本层任意模块可 import 它；**它自己不得 import 本层任何模块**。
- `ORCHESTRATORS`（层内编排）：可 import 本层其它模块；**不得被本层任何模块 import**。

当前声明：L1 `{contract}`；L2 `{settings, contract}` + 编排 `{pipeline}`。

**为什么这样切而不是把编排挪到 `tools/`**：`build_panel` 里是 L2 的业务判断（轴窗口怎么取、
填充语义、门禁顺序），放进 `tools/` 就等于把层内逻辑挪到层外，L2 无法作为整体被验证。
`tools/build_panel.py` 只做"解析参数 → 调 L2 → 打印 → 退出码"。

**为什么声明必须被校验**：白名单一旦只增不验，就会退化成"什么都能写"。
校验规则是双向的 —— 声明为共享叶子却 import 了本层、声明为编排却被别人 import、
声明的文件根本不存在，三种都报 FAIL。

## 3. 裁定："面板内所有值单位一致"按字面不可能（`startup.md` 风险 3）

面板里同时有 `USD_MILLION`、`PERCENT`、`INDEX_POINT`、`JPY_PER_USD`、`USD_PER_BARREL`，
而 L0 `units` 禁止跨族换算。要求"面板一个单位"只有两条路：跨族换算（已被 L0 禁止）或改 L0（破坏单位体系）。

**裁定**：不变量改为"**同一 `series_key` 内单位唯一**"。这保住了原文想防的事
（同一序列被两种单位混着写进面板），而不去要求一个物理上做不到的事。

## 4. 门禁口径的两个选择

**4.1 新鲜度用交易日而不是自然日。**
配置键因此从 `max_staleness_days` 改名为 `max_staleness_trading_days`。
理由：日频序列在周末/长周末会被自然日口径误判为"陈旧" —— 周五的值到周一就是 3 个自然日，
上限写成 3 就每周一都报警。交易日口径下该滞后是 1，且与"这个值被前向搬运了几个交易日"直接对应。
改名而非保留原名换语义：键名与实际口径不一致是隐性错误，比多打几个字贵得多。

**4.2 `min_trading_days` 换成 `min_real_observations`。**
原设计"每个序列至少 N 行"是错的：前向填充会把任何一条真实观测复制成很多行，
总行数几乎恒等于时间轴长度，这个门禁根本拦不住东西。
改成"每个序列至少 N 条**真实观测**（`fill_flag=False`）" —— 它才是"填充不得伪装成观测"的对应门禁。
取 3 的理由：下游算任何差值至少要 2 条真实观测，取 3 是留一条余量。

**被否决的方案**：再加一个 `max_fill_ratio`（填充点占比上限）。否决理由 ——
周度序列放在日度轴上，填充占比天然就有 80%（WALCL 实测 51 行里 41 行是填充），
这个阈值只会制造误报，而它想防的事（整列都是填充）已经由 `min_real_observations` 拦住。

## 5. `series_key` 约定的唯一实现放在 L1

`fred:walcl` / `cboe:vix` / `yahoo:^GSPC` 这套拼法散落在配置注释、自检、组装三处就会各自漂移。
**裁定**：唯一实现在 `L1_接入层/observations.py` 的 `series_key_*` 函数里，
`tools/selfcheck_l2.py` 用它做 `sources.toml` ↔ `normalization.toml` 的**双向**覆盖核对
（漏一个序列报错；配置里写了但源里没有的僵尸条目也报错）。

## 6. 为什么 CBOE PCR 不产出观测

`cboe_ratios.json` 里只有三个比值，**没有日期**。CBOE 页面上的交易日需要额外解析，
而现有适配器只解析了数值。用落盘目录名当日期等于编造一个日期 —— 比缺失更糟。
**裁定**：`observations.py` 不产出 PCR 观测；三个键在 `normalization.toml` 的 `[pending]` 里
逐条写明原因，`build_panel` 遇到 pending 键是**显式跳过**（不是静默丢弃）。
补上"解析页面交易日"这件事留在 OPEN-RISKS。

## 7. 本会话修掉的三处缺陷（都是反证逼出来的）

**7.1 日历漏掉跨年的顺延休市 —— 真缺陷。**
元旦 1/1 落在周六时会**提前到上一年的 12/31**，但 `holidays(year)` 原来只求本年的规则，
所以 2021-12-31 永远查不到。修法：求值 `year-1 / year / year+1` 三年再按 `day.year` 过滤。
这个缺陷是"配置篡改反证"逼出来的 —— 只有把 `saturday_shift` 改成 `true` 再断言
"2021-12-31 应变休市"才能暴露它。纯"跑通"型测试永远不会发现。

**7.2 `panel_store.read_panel` 声明的异常类型不实。**
模块声明"文件级问题抛 `PanelStoreError`"，但 `make_panel` 抛的 `PanelError`（`ValueError` 子类）
会直接漏出去，调用方按声明捕获会漏掉。修法：包成 `PanelStoreError` 并 `from exc` 保留原因链。

**7.3 `port_fidelity.py` 的连带误报。**
原实现遇到"函数集合不一致"就 `continue`，导致该模块**已申报的全部差异**被误报成"白名单过期"，
一个真问题被一个假问题盖住。修法：不再 `continue`，改为比对函数名交集；
集合差异单独判定。顺带引入 `EVOLVED_MODULES`（声明"迁移后有意演化"的模块，需给理由），
让"有意演化"和"未申报偷改"能被区分开。
